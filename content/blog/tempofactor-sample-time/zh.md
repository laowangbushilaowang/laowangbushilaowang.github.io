同一份发育样本里，可以同时找到祖细胞和成熟细胞。它们的样本年龄相同，表达状态却差得很远。反过来，不同年龄的样本，也可能包含状态相近的细胞。

从表达里读出时间，很容易走捷径：模型可以学会认细胞类型，也可以学会认实验批次，然后给出一个看起来不错的年龄。我们真正想知道的，是表达里的哪些变化跟样本阶段有关，哪些跟细胞自身的发育状态有关。

我在[早期两条时间轴的探索](/zh/blog/niche-time-pseudotime/)里讲过这个起点。后来的 SCage / TempoFactor，把任务收到了一个更具体的模型上：**输入单细胞表达，学习细胞表示并预测样本阶段，再用这个模型分析基因和空间组织。**

这是广州实验室的团队研究。我参与模型重构、从原始数据复现、对照实验、基因归因和图表分析。接手时，团队已经有了算法与流程；我做的一项工作，就是弄清楚分数背后究竟发生了什么。

## 为什么要分 Shared 和 Time

单细胞测序得到一张“细胞 × 基因”的矩阵。每个细胞有成千上万个表达读数，而我们知道的时间，通常只是这份样本采自哪个阶段。一个样本里所有细胞共享这个标签，并不意味着它们具有相同的成熟程度。

TempoFactor 建在 scVI 风格的变分自编码器上。编码器把高维表达压成低维表示，解码器再用这些表示重建表达；计数数据用 NB 或 ZINB 等分布建模，而不是把所有读数当成普通连续数做平方误差。[scVI 的模型说明](https://docs.scvi-tools.org/en/stable/user_guide/models/scvi.html)解释了这个基础。

在这个基础上，我们把表示分成两部分：

| 部分 | 设计上希望它承担什么 | 具体怎样使用 |
|---|---|---|
| `z_shared` | 保存较丰富的细胞状态信息 | 表达重建、整合可视化、基因归因 |
| `z_time` | 提供紧凑的样本阶段相关表示 | 时间预测，同时参与表达重建 |

![TempoFactor 编码器、两部分隐空间、解码器与时间监督](/images/tempofactor/architecture.webp)

*项目原 PPT 的结构图。图中 Intrinsic 对应正文的 Shared，是设计职责的命名，不表示已识别出纯粹的内在发育因素；这版示意画的是 24+2 维，后文实验还使用了 24+4。底部列出可选训练约束，具体实验不一定全部启用。*

两部分都参加表达重建，做法也有区别。Shared 经由非线性解码器产生表达基底，Time 经过线性层产生每个基因的调整量，二者在 logits 中相加，再归一化成表达比例。可以把主要关系压成几行：

```python
# 省略批次、采样和计数分布参数的结构示意
z_shared, z_time = encoder(counts)
gene_logits = log(shared_decoder(z_shared)) + time_decoder(z_time)
expression_proportion = softmax(gene_logits)
predicted_stage = time_head(z_time)
```

这个设计让 Time 参与“怎样解释表达”，而不只是外挂一个年龄回归器。但它也带来一个要实测的问题：Shared 会不会仍然装着大量时间信息？把向量切成两段，计算上很容易；让两段分别对应我们想要的生物因素，难得多。

### 时间标签属于样本，损失也要照顾样本

如果某个样本测到几万细胞，另一个只测到几千细胞，直接按细胞平均时间误差，细胞多的样本就会更有话语权。

模型提供按样本汇总的监督。在 `cell_agg` 模式下，先得到每个细胞的时间预测，再在同一样本内求均值，用这个均值与样本标签比较：

$$
\hat t_s=\frac{1}{n_s}\sum_{i\in s}h(z_{\mathrm{time},i}).
$$

这里 $s$ 是样本，$n_s$ 是参与这次汇总的细胞数。Huber loss 约束预测值接近标签，rank loss 约束不同阶段的先后顺序。实现还提供批次、样本内变化和两部分交叉协方差等约束的开关，便于分别测试；它们不是打开后就自动获得生物学解释的保证。

## 先弄清楚，模型到底没见过什么

我最初复现时留出了部分 donor；团队原流程则逐次留出一个样本阶段。两边都叫“留出验证”，结果却不能直接对齐。

**留出 donor** 问的是：换一个样本，还能不能预测？**留出 stage** 问的是：这个阶段没有参加时间监督，还能不能把它放到时间轴上？如果训练集仍有同龄 donor，前一个问题通常不包含后一个问题的全部难度。

后来我把流程改成按阶段逐折运行，并分别看细胞和样本层面的结果。下面是胎肺的一轮历史实验：12 个 donor、8 个阶段，每个 donor 抽取 1,200 个细胞。样本预测取细胞预测的中位数。

| 方法 | 样本 MAE ↓ | 样本 Spearman ↑ |
|---|---:|---:|
| TempoFactor | 0.763 | 0.796 |
| TemporalVAE | 0.819 | 0.810 |
| scVI + MLP | 0.937 | 0.627 |
| Harmony + MLP | 0.917 | 0.662 |

这一轮的标签把八个阶段编码为 0–7，所以 **MAE 的单位是阶段编码，不是孕周**。TempoFactor 的 MAE 更低，TemporalVAE 的排序相关更高；“预测更准”需要说清到底指什么。

复核实现还发现，这张表并不是完全对齐的信息访问比较：Harmony 用全部表达一起构建表示；scVI 对查询数据额外适配了 8 轮；TempoFactor 没做查询训练，并删除查询端时间标签。高变基因也是在划分前统一选择的。这一轮适合帮助定位实现差异，不能当成严格盲测下的最终模型排名。[TemporalVAE](https://www.nature.com/articles/s41556-025-01787-7)是外部方法，这里的结果也只对应本项目这一轮运行。

![胎肺 Shared 表示按样本阶段、预测时间、细胞类型和 donor 着色](/images/tempofactor/lung-umap.webp)

*同一 Shared UMAP 的不同着色。它来自全数据训练的可视化模型，不是上表的折外预测。看细胞类型是否保留、时间信号落在哪里，以及 donor 是否形成单独分区，有助于提出检查问题；二维图本身不能证明泛化或干净解耦。*

这次复现改变了我看 benchmark 的习惯。先问每个方法看到了哪些数据、在哪一层汇总，再讨论小数点后几位。否则，两份看起来差不多的 notebook，可能在回答不同的问题。

## 基因排序：先改“在哪里平均”，再换复杂算法

预测阶段只是中间一步。我还想从模型里找到值得继续研究的基因。

一种读法是看输入对表示的梯度；另一种是把某个基因的输入置零，再看表示变化多少。前者看局部敏感性，后者看一次指定扰动下的变化。两者都在问模型依赖什么，不能直接当成真实敲除实验。

我们在肠道、肺、视网膜、小脑、性腺、肢芽和两组脑发育数据上比较这些排序。为了有一个可检查的目标，我结合发育文献整理、复核参考基因，再看固定候选预算下能找回多少。名单里包含发育、细胞身份和功能相关基因；名单外的基因不等于负例，因此这里的“恢复”也不是发现新基因的准确率。

十月的一次分析，把问题从“换哪种归因算法”拉回到了一个更基础的地方：**这个基因的影响，应该在哪些细胞里统计？**

以只在少数细胞中检出的基因为例。把输入置零后，大量原本就是零的细胞几乎不发生变化。若把它们一起平均，真正发生变化的少数细胞就被冲淡了。肺数据中的 FOXJ1，是检查这类现象的一个具体例子。

于是，读出改成先选出检测到该基因的细胞，再平均扰动对 Shared 的影响：

$$
S_g=\underset{i:x_{ig}>0}{\operatorname{mean}}
\left\|z_{\mathrm{shared}}(x_i)-z_{\mathrm{shared}}(x_i^{g\leftarrow0})\right\|.
$$

这个公式只解释汇总思路；打分实现中的尺度归一化还要保持一致。它解决的是信号稀释，也会让检出细胞很少的基因更依赖少量观测，因此仍需要看 donor 和细胞类型覆盖。

固定在各数据集前 10% 的候选预算，八组参考记录的合计如下。同一个基因在不同数据集中出现，按各自记录计数。

| 读出方式 | 找回参考记录数 |
|---|---:|
| 原 Shared 评分 | 553 |
| 置零影响，在全部细胞中平均 | 279 |
| 置零影响，只在检出细胞中平均 | 575 |
| Saliency 同样只在检出细胞中汇总 | 569 |
| 条件置零 + 解码表达变异，等权合榜 | 631 |
| scVI 使用同类合榜读出 | 622 |

575 对 279，让我更重视汇总对象的选择；569 则提醒我，不能把全部改善都归给“置零”这个算法名称。

之后的合榜用了两种不同信息：输入端看模型识别细胞时依赖哪个基因，输出端看解码器预测的该基因表达在细胞间有多大变化。CDX2、NEUROD1 等参考更靠解码端补回。但合榜不是只加不减：相对条件置零单独的 575 条，补回 106 条，也挤出了 50 条，最后才是 631。

![八个数据集中的候选预算与参考基因恢复曲线](/images/tempofactor/gene-recovery.webp)

*横轴是读到排名前多少百分比，纵轴是恢复的参考比例。红线为条件置零与解码变异合榜。原图未画旧 Shared 和同读出 scVI；前 10% 的完整比较应结合上表的 553、631、622 一起看。不同组织的差距也不同，不能只挑肺数据的陡升。*

631 与 622 很接近。这一步支持了读出方法值得继续验证，还没有证明双隐空间架构带来独有优势。我不想靠不断调整名单，把一篇模型论文调成一张更好看的榜单。接下来需要冻结规则，在未参与这些选择的数据和 donor 上检验。

## 把时间放回空间，解释就更难了

时间预测的一个下游用途，是映射回组织切片：相同采集阶段，哪些位置的表达更像较早状态，哪些更像较晚状态？

在胎盘探索里，我们关注迷路层滋养层细胞，以及靠绒毛膜板的 LaTP/Chorion 区域。这里的 LaTP/Chorion 是空间区域标签，里面可以混有多种细胞状态。模型预测时间扣去同阶段参照、在切片内标准化后，得到相对时间残差。

![MPSTA 与 STAMP 胎盘中的解剖、时间残差和空间位置对照](/images/tempofactor/spatial-map.webp)

*原分析图：上排 MPSTA，下排 STAMP；左列提供解剖背景，中列显示各自图谱中的时间残差，右列是区域或距离参照。蓝色表示相对参照更早，不表示细胞移动方向或发育速度。两套图谱分别建模和标准化，颜色数值不能直接跨图谱相减。*

MPSTA 中，靠 LaTP/Chorion 的宽泛滋养层群体呈现较早的预测程序。但到外部 STAMP 数据，预设空间方向只在 3/5 张可定位切片上同向，没有稳定复现；用来辅助判断成熟状态的独立基因模块，可靠性也不足。

这里有几种解释仍然缠在一起：区域里早期状态的细胞更多、同类细胞内部状态不同、测序与注释差异，或者位置确实关联某种表达程序。时间残差能帮我们提出问题，还不能把这些解释拆开。切片上的许多点，也不能代替许多个独立胚胎。

所以这部分我保留为局部空间关联与后续假说，不写成“发现某个位置让细胞发育变慢”。要谈速度，需要时间刻度和跨阶段对应；要谈位置造成的改变，还需要更直接的重复与干预证据。

## 双隐空间还需要回答什么

走到后面，我越来越在意一个问题：把表示分成 Shared 和 Time，是否真的比一个容量相当的单隐空间模型多解决了什么？

视网膜的一次固定权重读出检查很直接。把 24 维 Shared 与 4 维 Time 拼成 Joint28，再按事先约定的梯度汇总方式做基因排序，结果没有更好：

![视网膜 Shared24、Time4 和 Joint28 的参考基因恢复](/images/tempofactor/joint-readout.webp)

*同一全细胞池、同样前 10% 预算，Shared24 恢复 75/96，Time4 为 24/96，Joint28 为 59/96。Joint 只是表示拼接，不是另训的模型；这个结果检验的是这一种拼接读法，不代表所有组合方式都无效。*

多给读出几个维度，不会自动带来更多有用信息。历史 24+1 的容量匹配实验，也没有证明双空间优于单空间。Shared 保存时间信息、Time 之外的方向仍影响重建，这些都让“干净解耦”成为要检验的目标，而不是结构图上的既成事实。

我现在更关心的研究问题，是同龄细胞可能有不同的成熟进程，而一个细胞内部的多个发育过程也未必同步。但要从快照中分清这些因素，首先得有可比较的样本：同龄而成熟程度不同，或者年龄不同但状态相近，再配合独立的成熟证据。缺少这种覆盖，加模块和加约束都很容易得到漂亮却含混的表示。

目前原模型仍是基线，新的模块化约束在小规模隐藏基因预测中也没有稳定胜出。这个项目还在继续。对我来说，下一步该争取的结果很具体：在真实留出样本上，证明一个明确的新设计究竟改善了什么，而不是再给两块隐空间换一组更动听的名字。
