看到网上有人让 AI 玩《杀戮尖塔 2》，我也想试试。用的是 [CharTyr/STS2-Agent](https://github.com/CharTyr/STS2-Agent)，框架已经有游戏 Mod 和 MCP Server。我借助 Codex 在 Mac 上接通，补了一处构建脚本，然后实际打了几个回合。

## 先让游戏把局面交出来

这套方案不靠截图认牌。游戏内的 C# Mod 读取手牌、能量和敌人状态，Python 将本地接口包装成 MCP 工具，Codex 决定下一步。

![Mod、MCP 与决策之间的链路](/images/sts2/mcp-loop.svg)

*本地 v0.5.2 的接入示意，非游戏截图。框架由 CharTyr 开发；状态向模型流动，动作返回游戏，再读新的局面。*

当时 Mac 走源码构建。编译过了，健康检查却没起来，对照 Windows 脚本才发现 shell 脚本漏复制了 `mod_id.json`。游戏需要的三个文件是：

```text
mods/
  STS2AIAgent.dll
  STS2AIAgent.pck
  mod_id.json
```

补上存在检查和复制逻辑，同时处理启用设置、安装位置后，游戏端返回了 `ready`。这处小补丁现在还在本地工作副本里。先查 Mod 有没有加载，再查 MCP 能否读到状态，比直接猜模型哪里出了问题有效。

## 打出一张牌，索引就可能变了

我要求每步先读 `state` 和 `available_actions`，再出牌。第一次实战，铁甲战士对小啃兽：

| 操作 | 实际返回 |
|---|---|
| 第 1 回合：痛击、打击 | 敌人血量 42 → 34 → 25，能量耗尽 |
| 结束回合，等待可操作 | 第 2 回合，自己 80 → 68 血，恢复 3 能量 |
| 第 2 回合：打击、两张防御 | 敌人 25 → 16 血，格挡 0 → 5 → 10 |

这里最容易忽略的是索引：最初的手牌 3 是“痛击”，打出后，手牌 3 已经变成了“打击”。不能读一次手牌，就把后面几步的数字全部排好。每次出牌、抽牌或弃牌后，都要重新取索引。

结束回合后，返回仍写着 `COMBAT`，但可用动作已经为空，需要等下一次行动窗口。简化状态里的部分卡牌文字还带数值占位符，判断伤害时也得看更完整的返回，不能全靠模型记忆。

这次在第二回合中途停了，只验证了读状态、出牌和等待，没有打完一局。实际调用的是 MCP 工具，未加载专门的游玩 Skill；仓库自带的 Skill 和多 Agent 交接属于原框架的能力。

## 移走 Mod，存档还会留下状态

几天后，我要求卸载，因为游戏一直进入 `modded` 存档。三个 Mod 文件移走并留了备份，但再次启动时问题还在。继续查，设置里仍保留着启用记录，普通档和 Mod 档也分别存放。

我没有直接删除或合并存档，后续清理设置能否切回普通档也未继续验证。这个小实验留下的经验很具体：接入时看状态与动作，停用时还要查设置和存档，光移走程序文件未必就结束了。
