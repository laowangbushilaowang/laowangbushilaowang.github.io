我做这套规划时，刚解锁姜岛，矿洞门口已经放了几十个宝石复制器。农场里有八个鱼塘，想发展羊毛织布，也想慢慢转向酿酒。两个人一起玩，房子和马厩还得考虑两个人出门。

需求听起来不难：好看、赚钱、少走路，最好不用把现有农场拆了重建。

但前几轮蓝图里，道路穿过池塘，后面又出现了穿过农田的路；建筑挤在畜棚附近，门前空间也没留好。我原本是在规划退休生活，结果先得处理交通问题。

后来，我和 Codex 把它做成了一个本地网页工具：用真实游戏素材画地图，给建筑和道路标出格子坐标，切换初期、中期、末期方案，再检查重叠和入口。它更接近一份可以逐项核对的施工蓝图。

## 先保住现有农场，再谈终局

![最初提供的农场布局照片](/images/stardew/starting-layout.webp)

*最初用来讨论改造的布局照片，屏幕里是 Stardew Planner。中央农田、左下八鱼塘和右侧动物区已经有了位置；它们是规划起点，不能只为一张终局图就全部推倒。照片裁去了浏览器边栏。*

我想要的并不是单一的最高收益路线。羊毛做布可以作为一条生产线，果实酿酒则慢慢扩起来；鱼塘可以缩减，但仍想保留不同鱼种。于是，问题变成了怎样安排建设顺序。

酿酒也不只是多放小桶。[小桶配方](https://stardewvalleywiki.com/Keg)需要橡树树脂，建成后还要持续有果实喂进去。因此我把树脂林、温室和姜岛供料，与小桶扩张放在一起规划。否则机器造出来，原料没跟上，地图只是多了一排空桶。

当时确定的节奏是先用牧羊人职业支持羊毛布这条线，同时准备酿酒产能；等小桶和果实供给接上，再考虑切到工匠。鱼塘从八个减到六个，也放到中期，而不是一开始就拆。

这些都是围绕我的偏好制定的建设规则。它没有算出全游戏的最优收益，也没有证明某个机器数量适合每一份存档。

## 建筑的图片、占地和门口，是三套信息

最初的文字分区还不够用。“动物区放在东边”，并没有回答畜棚到底放在哪一格、门朝哪边、筒仓会不会挡路。

我参考了 [Stardew Planner](https://stardew.info/) 的地图呈现方式，把方案放到 80×65 的标准农场网格上。网页用 Canvas 绘图，每格对应原始画布的 16 像素；建筑从精灵图集中取出，坐标按格子记录。

这里需要分清三件事：

| 信息 | 用来解决什么 |
|---|---|
| 建筑精灵的像素范围 | 屋顶、墙面在图上怎样显示 |
| 建筑的地面占地 | 哪些格子被实际占用，是否与别的建筑重叠 |
| 入口相对占地的偏移 | 玩家要站在哪一格，才能进门 |

房子的屋顶往上伸，不能把整张图片都当成地面障碍。实现里会按占地底边放置精灵；检查碰撞时，再使用单独的占地矩形。

例如，方案中的羊棚以 `(60, 33)` 为占地起点，大小为 `7×4`。入口规则相对起点偏移 `(3, 4)`，因此需要检查门前的 `(63, 37)`：

```javascript
building = { col: 60, row: 33, width: 7, height: 4 };
entry = { x: building.col + 3, y: building.row + 4 };
// 接下来检查门前能否站人、能否走到道路
```

这是从实际配置简化出来的例子。现在改建筑位置，就有明确的对象可改，不必再用“再往旁边一点”来描述。

## 从门口出发，检查有没有路可走

我在改图时反复指出的几件事，后来变成了程序里的检查：建筑不能互相压住，路不能穿主要水域或农田，预留地不能悄悄被占掉，建筑门口也要能进出。

入口检查还多了一步搜索。先把地图变成可走与不可走的格子，再从门前出发，逐层检查上下左右的相邻格子，直到找到道路，或者没有新的格子可走。这就是广度优先搜索（BFS），在这里用来回答一个很小的问题：**这个入口能不能到达道路？**

```text
建筑配置 → 占地格子 → 门前位置
                         ↓
               能站人？门前够宽？
                         ↓
                从门口搜索到道路
```

这一步有用，但不能让它承诺过多。当前搜索检查的是能否到达某一块道路，不会证明全部道路属于同一张连通路网。水域也是手工近似的范围；围栏、机器和游戏里全部地形碰撞规则，并没有完整搬进来。绘图时跳过水格，也不等于自动找到了一条绕池塘的路。

所以我把它当成修改蓝图时的辅助检查，再看整体地图和出入口。当前三阶段页面都能加载，也没有触发这套检查的警告；最终能否照图放置，仍要回到游戏里核对。

## 三个阶段，解决三个不同的问题

初期方案要能开始做，中期要能接着扩，终局才考虑大规模生产。三张图使用同一套坐标和图层，方便对照哪些建筑新增了，哪些地方先空着。

![初期农场蓝图](/images/stardew/early-map.webp)

*初期规划视图：保留八鱼塘，整理道路、树脂林和动物区，同时留出后续建设的位置。图中是规划配置，不代表这些升级已经在存档里完成。*

![中期农场蓝图](/images/stardew/mid-map.webp)

*中期把鱼塘减为六个，增加动物与加工设施。主要区域延续初期的位置，改造不需要每次从一张空地图重新开始。*

![末期农场蓝图](/images/stardew/late-map.webp)

*末期增加棚屋、小屋和交通设施。它展示目标布局；姜岛的供料安排另有文字计划，不在这张主农场地图里。以上均为本地规划器的实际界面截图，游戏素材属于原作者。*

我还反复问过，剩下的空地以后做什么。后来预留地有了用途和启用条件：西侧机动林地应对树脂或木材不足，东南扩建地可留给棚屋，也可以改成花园。暂时不建，是为了保留选择；界面会用半透明图标提示未来用途，避免看起来像忘了画。

每日路线也按操作频率组织。动物、温室和常用加工设施尽量一圈处理；鱼塘、地窖等按各自周期安排。路线是人为设计的作业顺序，没有用优化算法证明它是最短路径。

## 地图之外，还需要一张下一步清单

网页负责回答“放在哪里”，另一个小 Python 脚本负责回答“接下来先做什么”。输入是手动填写的农场状态，包括建筑等级、机器数量、职业和供料规模；输出是按固定优先级排列的行动。

比如，没有加工棚时先安排第一个棚；小桶扩张时检查树脂供应；职业切换则等小桶和果实供给达到预设条件。每条建议都有原因和目标，避免只得到一句“继续扩大生产”。

这部分很简单：规则判断、排序、打印清单。它不会读取游戏存档，也不会自动更新网页的三阶段布局。状态文件和周表仍保留着初始化数据，所以我没有把“中午前做完日常”“切换职业后收益增加”这些目标写成实际结果。

对这次小项目来说，真正做出来的是三阶段可视化蓝图、坐标与入口检查，以及一套建设清单。收益测算和自动布局求解还没有做到。以后再让 AI 帮我改图，我会先给占地、入口和不能动的区域，再谈想要多少机器；这样至少能尽早发现那座门前又被塞满的畜棚。
