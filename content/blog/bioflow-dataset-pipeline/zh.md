我在广州国家实验室做 BioFlow，是为了整理公开多组学数据，给虚拟细胞模型准备数据语料。手工做这件事，要找论文、追数据来源、下载和解压，再逐份读文件、对应样本、整理元数据。

我想让 Agent 接手其中反复阅读和判断的工作，同时让数据处理能稳定执行。项目先尝试过更自由的 Agent，后来改成五阶段工作流；后续又在 Nova / Sentinel 中探索任务调度与纠错。

这篇重点讲我做过的三个选择：

- **把 Agent 的自由度放在判断上。** 模型选择读法，已有工具负责读取和写入；出了问题可以分别检查。
- **给模型看文件关系。** 文件树、样本表和来源路径，比把整份矩阵放进上下文更适合这个任务。
- **按数据类型决定输出。** 能构建矩阵的走矩阵流程，尚需专门处理的先保存文件集合和样本信息。

## Agent 的自由度与工作流设计

早期我部署过本地模型，也试过让 Agent 自己编写、修改 loader，也就是读取数据的程序。我的考虑是：附件格式这么多，能不能遇到一种新格式，就让它现场处理？

尝试中出现了幻觉和不稳定修改。程序能运行，还要确认它读了正确文件、矩阵方向没反、样本没有合错。出了问题，既要查数据，又要查临时生成的代码，检查范围变得很大。

后来我选择更有约束的流程，类似 LangChain 式的显式编排：先规定步骤、输入输出和可调用工具，再让模型处理其中不容易写死的判断。

| 方案 | 模型可以做什么 | 我需要检查什么 |
| --- | --- | --- |
| 早期自由 Agent | 根据数据现场写、改 loader | 文件选择、代码行为和输出是否正确 |
| 受约束工作流 | 根据线索选择已有 loader、给出结构化计划 | 选择是否合理，以及对应工具的输出 |

这次调整把模型的职责集中到三个地方：

| 判断点 | 提供给模型的材料 | 后面的程序负责什么 |
| --- | --- | --- |
| 找数据来源 | PDF 正文与数据编号线索 | 检查提取结果、保存编号表；正则有效命中时先返回 |
| 选择数据读法 | 文件树、候选文件、少量说明 | 调用已有 loader，读取、转换和写入 |
| 整理元数据 | 原始字段、论文或辅助表、规范词表 | 标准化能确定的字段，补缺并保存结果 |

我的经验是，判断和执行应该分别能检查。比如模型选错了文件，就看它收到的目录与计划；某种格式读错了，就修对应的 loader。如果模型规划的路径没有得到预期产物，外层 builder 还可以尝试确定性构建。

### 固定步骤之后，怎样增加自主性

我仍希望它能长期运行、遇到错误后继续处理。这是后来 Nova / Sentinel 的方向：保留数据处理工具，让 Agent 和调度层负责计划、异常处理与恢复。

Skills 说明每一步怎样操作；任务状态记录已经做到哪里；重试规则区分下载超时和数据不适用。一个任务的失败，也不应让已经完成的步骤全部重做。它们共同服务于同一个目标：减少反复盯着流程处理异常的工作。

Nova 是设计，Sentinel 实现了部分队列、状态、worker 和重试逻辑。历史小样只完成了第一步，第二步失败后阻塞了后续阶段，长期无人值守尚未完整验证。

## 用文件结构理解数据、对应样本

工作流明确以后，第四步的数据构建依然需要判断：下载下来的文件，应该怎样组织成数据？

以常见的 10X 格式为例，矩阵、特征表和 barcode 表需要一起读取。下面是简化示例，样本名用于说明，并非某次运行截图。[10x 格式说明](https://www.10xgenomics.com/support/software/cell-ranger/latest/analysis/outputs/cr-outputs-mex-matrices)

```text
downloaded_dataset/
├── sample_A/
│   ├── matrix.mtx.gz
│   ├── features.tsv.gz
│   └── barcodes.tsv.gz
├── sample_B/
│   ├── matrix.mtx.gz
│   ├── features.tsv.gz
│   └── barcodes.tsv.gz
└── sample_metadata.tsv
```

**目录提供了两组文件的归属关系。** `sample_A` 的三个文件应该配成一组，`sample_B` 也是。末尾的 metadata 表补充样本说明，不能当作第三个表达矩阵读取。

实际数据可能按文件名前缀区分样本，或者套着压缩包、混有处理后的表格。只匹配扩展名容易漏掉这些关系。我让程序先提取文件结构和文本线索，再交给模型判断。模型返回一个读取计划：用哪个 loader，读哪些文件，每组文件怎样搭配。

![从文件线索到读取计划和样本编号](/images/bioflow/file-to-sample-zh.svg "按 probe、planner、样本解析和编号映射代码重绘；sample_A/B 为教学示例。")

这里有三个需要分清的步骤：

1. **找到该读的文件。** 对 MTX，计划中的一个 item 同时指定 matrix、features、barcodes，程序照计划执行。
2. **把读入数据对应到样本。** 使用可用的 SDRF、GEO series matrix 映射和来源路径；另一个 LLM 环节根据已有编号、细胞数和文件线索生成旧编号到新编号的映射。
3. **把样本对应到研究条件。** 再从数据库、论文和补充材料整理组织、年龄、处理条件等字段。

文件树解决“材料怎样摆在一起”，样本映射解决“数据属于谁”。这两件事都做好，合并后的矩阵才方便继续分析。

![BioFlow 原设计说明书中的数据关系图](/images/bioflow/sample-relations-original.webp "BioFlow v0.2 设计说明书原图，压缩为 WebP。Dataset、Sample、Cell、Donor 分层保存不同信息；图为关系设计。")

### 怎样检查 AI 给出的对应关系

程序检查映射格式和部分完整性，失败时回退到路径标识。但路径标识只能保留来源线索，长得像 GSM 的编号也不证明生物样本身份正确。实际核对仍要回到原始样本表，检查有没有误合并、误拆分。

元数据也是如此。模型可以把不同写法映射到规范词，补充缺失信息；影响分析分组的字段则需要找到材料支持。当前写回只填空值或 `Unclassified`，已有非空值保留，因此旧值本身是否规范，也需要检查。

这部分经验对我最有用：**先给模型足够具体的上下文，再检查它建立的关系。** 单看文件是否生成，或者字段是否填满，判断不了数据能否用于分析。

## 多组学扩展：共用流程，保留不同的数据形式

最初的矩阵路径能处理一部分单细胞数据。扩展到其他组学时，我需要决定：哪些步骤可以复用，哪些输出不能照搬？

RNA 可以是细胞 × 基因，ATAC 可以是细胞 × peak；空间数据还要保留观测与坐标的对应。蛋白、代谢和影像的原始文件，往往需要各自的处理工具才能形成可分析的量。给它们换个扩展名，工作并不会自动完成。

我要求扩展时保留原有 RNA / ATAC 路径，并按组学类型分流：

| 数据类型 | 当前处理到哪里 |
| --- | --- |
| RNA / ATAC | 构建矩阵、整理样本与元数据 |
| 空间转录组 | 基本矩阵与 spot 坐标；缺坐标时明确记录 |
| 蛋白 / 代谢 / 影像 | 先收集文件、资产清单和数据集／样本信息，定量处理仍待接入 |

这样，文献、来源和任务管理可以共用，数据表示保留各自的要求。先把文件收好、对应关系整理清楚，后续才能接专门的分析工具。

BioFlow 后来用于团队实际数据收集。接下来我更想把一小组固定数据的对应关系核对完整：文件有没有配对正确，细胞属于哪些样本，分组字段来自哪里，再看流程能否在失败后恢复。继续增加数据量之前，这些是我会优先检查的东西。

早期脚本见 [Bio_dataflow](https://github.com/laowangbushilaowang/Bio_dataflow)；后续多组学扩展与 Sentinel 原型不全在该公开仓库中。
