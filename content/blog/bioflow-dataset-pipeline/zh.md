BioFlow 的一份提取结果里，没找到数据编号的记录也有值：`Not found`。

这当然不算找到。但如果统计时只检查“这一列是不是空的”，它就会被算进成功数。这样的细节很容易被忽略：CSV 写好了，程序也没有报错，看起来这一步已经完成。可接下来要下载什么呢？

我在广州国家实验室做 BioFlow，是为了收集公开多组学数据，给虚拟细胞模型准备语料。人工做这件事，需要从论文一路追到数据文件，再把样本信息整理好。大模型能读文本，也能写代码，我最初试过让 Agent 自己编写、修改读取数据的程序。但它在异构格式上会产生幻觉，修改也不稳定。后来我把流程固定下来，让模型在几个需要判断的地方帮忙。

这篇就沿着数据走一遍。先找到编号，再看看下载回来的东西怎么读，最后处理那些决定数据怎样分组的样本信息。[Bio_dataflow](https://github.com/laowangbushilaowang/Bio_dataflow) 放的是早期脚本；后面提到的多组学扩展和 Sentinel 原型不全在这个公开仓库里。

## 论文下载好了，然后呢？

一篇论文可能用好几份公共数据。找到数据库编号，也可能只是找到整个研究系列的入口，还没到具体样本。比如 GEO 的 `GSE` 对应研究系列，`GSM` 对应样本。[GEO 检索说明](https://www.ncbi.nlm.nih.gov/geo/info/qqtutorial.html)

我把流程拆成了五步：检索文献、下载 PDF、提取数据编号、下载并构建数据集、整理元数据。下面是原项目汇报里的流程表。

![BioFlow 原项目汇报中的五阶段表](/images/bioflow/workflow-original.webp "原项目汇报第 2 页：五个阶段及各自产物。由原表导出、裁切并压缩；点击可放大。")

每一步都保存自己的结果。这个安排最直接的好处是，出了问题能从中间接着查：提取器没找到编号，就看 PDF 有没有下载到、正文能不能抽出来；矩阵读不出来，就检查下载文件和 loader。修第四步，不需要把前面的论文再搜一遍。

因此我需要的状态也不只是“成功”和“失败”。没有 PDF，和读完 PDF 没找到编号，是两件不同的事。前者要处理下载，后者要回到论文或补充材料里找线索。后面的任务怎样继续，取决于这一步究竟做到了哪里。

## 先用正则找编号

`GSE`、`E-MTAB` 这些编号有固定的形式。正文能抽出来时，正则就能找出不少候选。BioFlow 先走这条路，检查编号是否出现在原文中、形式是否符合要求，再过滤一些明显的占位值。没有找到有效结果，才请 LLM 补找。

这不是正则和模型同时各找一遍。正则命中就返回，所以它也可能漏掉另一组编号。这是少调用模型所付出的代价。

2025 年 11 月 25 日那批记录很能说明问题。输入有 200 行，实际处理了 43 行，31 行有编号，12 行没有，其余 157 行跳过。报告里写的成功率是 `31/43 = 72.1%`。

再看同批 CSV，31 条有编号的记录全部来自正则；9 条走了 LLM，但没有找到编号；另外 3 条也没有编号，标为 `failed`。这批数据不能拿来证明 LLM 提高了提取效果。72.1% 也只到“提取出编号”为止，还没走到下载和构建。

即使编号确实在原文里，也得继续看它指的是什么。作者可能拿它做比较，也可能只是引用别人的工作。当前的原文检查能挡住一部分凭空生成的编号，却不能替我决定这份数据适不适合收进来。

## 下载目录里，文件之间的关系更有用

假设一份附件里有矩阵、特征表和条形码表。这是说明读法的例子：矩阵给数值，特征表告诉我们每个基因或 peak 是什么，条形码表对应观测。只拿矩阵文件，行列里的数字仍然缺少解释。

真实附件还会套着压缩包、按样本分目录，或者把数据存在 HDF5 里。这里模型能帮上的忙，是结合文件名、目录和说明判断应该用哪种读法。

BioFlow 先用 `probe` 摘出目录结构、候选文件和少量文本，再交给模型。模型返回 JSON，选一个已经实现的 loader，并指定要读哪些文件。Python 根据注册表调用它，完成读取和转换。没有必要把矩阵里的每个数字塞进模型上下文；它需要的是文件之间的关系。

这和早期让 Agent 现场改 loader 很不一样。现在选错了，我可以检查它看到的目录摘要、选中的工具和输入文件。格式适配出了问题，就修对应的 loader。模型路径没构建出预期产物时，外层 builder 还可以尝试确定性构建。

这套做法仍然会出错。目录太深或文件太多，摘要可能截掉关键附件；loader 写出了 `raw.h5ad`，也还要检查矩阵方向、重复特征和样本对应。我不想把“文件存在”直接当成“数据能用于分析”。

## 多组学扩展时，我没有把所有东西塞进 h5ad

[AnnData](https://anndata.readthedocs.io/en/stable/generated/anndata.AnnData.html) 可以把“观测 × 特征”的矩阵和注释放在一起。RNA 的特征可以是基因，ATAC 可以是 peak；空间转录组还要把观测和坐标对应起来。

但下载回来的质谱文件、显微图像，距离这样的矩阵还差各自的处理过程。统一后缀解决不了这个问题。

扩展 BioFlow 时，我要求保留已有 RNA、ATAC 流程。RNA、ATAC 和空间转录组继续走矩阵构建；蛋白、代谢和影像先收集文件，记录清单，整理数据集与样本信息。代码里通过 `OmicsProfile` 选择处理方式，输出目录也按组学分开。

![BioFlow 原项目汇报中的两类输出](/images/bioflow/output-modes-original.webp "原项目汇报第 3 页：矩阵构建与文件集合两类输出。Collection 完成文件收集及信息整理，尚未完成定量转换；点击可放大。")

这样至少可以先把材料收好，知道从哪里来、包含什么，再接各自的分析工具。蛋白和代谢的定量标准化、影像分割与特征提取都还没有在 collection 模式里完成；空间转录组目前接的是基本矩阵和 spot 坐标。

## 元数据补全，最怕的是一个像真的答案

数据读出来以后，还得知道它来自哪里：哪个组织、什么时间点、用了什么测序方法。这些信息可能在数据库字段里，也可能写在文件名、论文或补充表中。同一个概念有不同写法，模型做文本匹配很有用。

BioFlow 先用规则和词表处理已有字段，再让 LLM 对照原始 metadata 和相关文本补缺。写回时只填空值或 `Unclassified`，非空字段保留。这样少了一些覆盖已有信息的风险，但已有值写得不规范，也可能原样留下。

我宁愿在这一轮留下 `Unclassified`。空值会提醒我还要找材料，一个看起来合理的时间点却可能直接被用于分组。比如把模型补出的时间点用于比较不同阶段，补错了，后面的图照样能画出来。这个例子说明的是分析风险，不是某次实际实验的结果。

所以补全率不是我唯一关心的数字。要拿这些字段做严格的跨数据集分析，还得知道答案从哪段材料来，并做人工抽查。这部分来源记录和核验仍需要补上。

## 后来，问题变成了任务停下来以后怎么办

五个阶段能分别重跑，还不等于整条流程可以放心放着运行。下载卡住，要不要重试？一个 accession 正在处理，另一个 worker 能不能再领一次？进程断了，哪些结果可以保留？

Nova 的设计把整次运行、单个任务和每次尝试分开记录，后来的 Sentinel 原型实现了其中一部分：SQLite 状态库、worker、重试分类和 heartbeat。一次失败可以保留自己的尝试记录，再安排下一次。Skills 描述每个阶段怎么做，真正执行和保存状态仍由程序负责。

历史的小样 `tiny_e2e` 没有走通五步：第一步成功，第二步永久失败，第三至第五步被阻塞。这也是原型目前的实际边界，不能把它写成已经完成的无人值守系统。

恢复逻辑还有需要修的地方。heartbeat 由独立线程更新，线程活着时，真正干活的子进程仍可能卡住；任务重新排队后，旧 worker 也可能迟到写回结果。下一步需要给执行加超时，并核对写回结果属于哪次尝试。

如果继续做，我会先固定一小组数据，逐项检查矩阵方向、样本对应和元数据来源。哪一项没通过，就保留对应的失败原因和文件，再决定是修 loader、重试下载，还是回到论文里补材料。
