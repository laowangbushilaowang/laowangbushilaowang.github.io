复现一张图，先得知道它属于哪一轮分析。同样的模型，换了数据筛选条件或上游结果，图的含义就可能变。让 Agent 从一堆 Notebook 里挑“看起来最新”的那个，我很难确认它接的是不是当前主线。

我在研究工作区采用的约定是：每轮分析有自己的目录，输入有出处，图表跟着产生它们的分析走；交接再指向当前任务。目录结构因此参与了分析判断：哪些结果可以继续用，哪些还只是一次试验。

## 每轮分析都有自己的目录

我把一个独立分析目录叫作 capsule。它对应一个分析版本，保存这一轮的 Notebook、参数和结果。下面按现有约定缩写了一个活跃复现工作区，实验名是教学占位，并非某次真实运行的截图。不同工作区沿用已有的 `analysis/`、`active_analysis/` 或 `active_analysis_reproduce/`，不为了统一名字搬动旧文件。

```text
research-project/
├── AGENTS.md
├── README.md                    # 导航与当前任务入口
├── data/                        # 共享原始输入，不逐轮复制
├── src/                         # 公共模型代码与稳定工具
├── active_analysis_reproduce/
│   ├── 01_baseline__01_compare__v1_pilot/
│   │   ├── README.md            # 问题、输入、输出、当前判断
│   │   ├── notebooks/
│   │   ├── configs/
│   │   ├── manifests/           # 输入来源、版本与参数
│   │   ├── tables/
│   │   ├── figures/
│   │   └── results/
│   └── 02_validation__01_compare__v2_revised/
│       └── ...                  # 新一轮保留自己的记录
└── try/                         # 探索支线；活跃复现不读取
```

目录名带阶段、分析内容和版本。新增前先检查同层编号；一个新版本不会覆盖上一轮的模型或结果。`final`、`new` 这样的名字难以说明改了什么，我会把变化写进版本描述和 README。

共享数据、模型代码留在公共区。一个 capsule 按需要保存脚本、日志和检查记录，不必把所有文件夹都建齐。查看一张图时，顺着同目录就能找到参数和 Notebook；这些文件仍需要维护，目录整齐本身不能保证复现成功。

## try 留下探索，复现走明确依赖

`try/` 可以留住探索过程。我对**活跃复现任务**写了更严格的规则：它只能依赖公共原始输入或其他活跃 capsule，禁止读取任何 `try/`，也不能用软链接或间接路径绕过去。开始执行前要检查真实输入路径，并记进 manifest。

原因很具体：一个临时结果可能来自旧筛选条件、未完成的运行，或已经放弃的方案。如果下一轮悄悄把它当输入，报告里的方法和实际走过的计算就对不上。

![活跃复现的文件读取关系：规则与入口定位分析，明确输入进入当前 capsule，try 不进入复现依赖](/images/agent-analysis-path-zh.svg)

*按已核对的目录规则绘制的读取关系示意；箭头区分定位路径与数据依赖，不是运行截图。禁读 try 的范围是活跃复现任务。*

有价值的探索可以成为下一轮分析的起点。但进入复现主线时，需要把方法、输入和参数写清楚，建立可检查的新分析；不能仅把临时文件挪个位置或改个名字，就当它已经可靠。

## Notebook 要能看懂判断

分析目录解决“去哪找”，Notebook 要回答“为什么这么做”。我要求关键处理、筛选、统计和绘图逻辑在 Notebook 中能看到、能修改；稳定工具函数或训练命令可以调用。

一个用于数据比较的 Notebook，可以先说明比较问题与输入，再展示筛选前后的样本情况，接着给指标和图。看到指标变化时，读者能够回到前面的筛选与参数，判断差异来自哪里。这里描述的是组织方式，不是某项实验的结果。

每个关键小节先写目的和判断标准，完成后就展示相应表图并解释，再往下走。执行后保留 outputs。这样我检查 Agent 的分析时，可以追到具体选择，也能直接在那一步修改，而不用先拆开一个包办全部工作的脚本。

## AGENTS.md 告诉 Agent 怎样接手

目录约定需要写成能执行的规则。我会在项目 AGENTS.md 中说明适用范围和读取条件，例如：

- 新分析使用独立 capsule；沿用已有分析根目录和阶段编号。
- 活跃复现只读取明确允许的输入，禁止从 `try/` 接入。
- 核心分析过程在 Notebook 中可见，关键图表保留输出。
- 恢复旧任务或缺少背景时，先找已有入口和交接；小修改按需读相关文件。

交接保存当前采用哪个版本、卡在哪里、下一步，以及对应输入和结果的链接。比如“训练结束，评估待做”，就应保留这两个不同状态。

在 AIQuant，我把 Notebook 和清理工作的细则拆到专门文档，根规则保留读取入口。它的历史输入规则与研究复现规则分别维护，不能把一个项目的 `try/` 禁区照搬到所有项目。

交接一张图时，我要求同时给出它所属的 capsule 和生成 Notebook。下一次修改先对上输入与参数，再决定需要重跑哪一步。
